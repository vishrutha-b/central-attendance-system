DevSecOps & CI/CD Specification

Central Attendance Management System (CAMS)

Complete Automated Continuous Integration & Security Pipeline Reference
Document Purpose: This technical reference documents every stage, testing tool, and security scanner implemented in the GitHub Actions workflow (.github/workflows/ci.yml).

1. Directed Acyclic Graph (DAG) Pipeline Tree

To optimize execution speed and provide transparent feedback, the pipeline runs as an interconnected multi-job tree:

1. Root Gatekeeper
syntax-and-setup
Python compileall checks syntax across all files. Fast-fails early on syntax errors.
2. Code Quality
code-quality
Ruff linter and MyPy static type checks run in parallel.
3. Security Scans
security-scans
Bandit SAST, pip-audit CVE scan, Safety, and Gitleaks secret detection.
4. Automated Tests
test-suite
Spins up MongoDB 7.0 service container and runs Unit & API pytest suites.
5. SonarQube Gate
sonarqube
Aggregates coverage.xml from tests and evaluates Clean Code Quality Gate.
6. Docker Build & Scan
docker-build-and-scan
Builds Docker container and scans layers using Aqua Security Trivy.

2. Deep-Dive Stage Analysis

Stage 1: Syntax & Base Verification compileall

Objective: Fast-fail the pipeline in seconds if syntax errors exist before spinning up database services.

python -m compileall app/ tests/ scripts/

Stage 2: Code Quality & Type Checking Ruff MyPy

Objective: Enforce PEP 8 style standards, import cleanliness, and validate type consistency across FastAPI Pydantic models.

ruff check app/ tests/ scripts/
mypy --explicit-package-bases --ignore-missing-imports app/

Stage 3: Security Scans Bandit pip-audit Safety Gitleaks

Objective: Multi-vector security auditing to catch AST vulnerabilities, third-party library CVEs, and secret leaks.

bandit -r app/ -ll -s B104
pip-audit -r requirements.txt
safety check -r requirements.txt

Stage 4: Automated Testing & Coverage Pytest MongoDB 7.0

Objective: Runs isolated tests against live endpoints, measures code coverage, and archives test artifacts.

pytest tests/unit -v --cov=app --cov-report=xml:coverage.xml
pytest tests/api -v

Stage 5: SonarQube Analysis SonarCloud Quality Gate

Objective: Inspects test coverage, duplicate code, and security hot-spots. Cleanly skips if SONAR_TOKEN is not yet configured.

sonar-scanner (configured via sonar-project.properties)

Stage 6: Docker Container Build & Scan Docker Trivy

Objective: Assembles the deployable container image and scans for critical OS layer CVEs before deployment.

docker build -t central-attendance-system:$GITHUB_SHA .
trivy image --severity CRITICAL,HIGH central-attendance-system:$GITHUB_SHA
