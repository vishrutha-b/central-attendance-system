DevSecOps & CI/CD Specification

Central Attendance Management System (CAMS)

Automated Continuous Integration, Multi-Vector Security Auditing, Testing, and Containerization Architecture

Pipeline: .github/workflows/ci.yml Architecture: Directed Acyclic Graph (DAG) Python 3.12 MongoDB 7.0 Container SonarQube & Trivy
DOCUMENT PURPOSE
This document specifies the automated Continuous Integration and Continuous Deployment (CI/CD) pipeline for CAMS. It details every execution stage, testing framework, security scanner, and container verification gate.

1. Executive Summary & Pipeline Objectives

  • Fast-Fail Syntax Gate: Compiles Python AST across all modules in under 10 seconds before spinning up database resources.
  • Parallel Quality & Security Verification: Executes Ruff, MyPy, Bandit, pip-audit, Safety, and Gitleaks concurrently to minimize runtime.
  • Isolated Database Testing: Launches an isolated MongoDB 7.0 service container in GitHub Actions to run 39 Unit and API integration tests.
  • SonarQube Clean Code Gate: Tracks test coverage, code duplications, and security hotspots against defined quality standards.
  • Container Vulnerability Gate: Builds the production Docker image and validates container layers using Aqua Security Trivy.

3. Deep-Dive Stage Analysis

Stage 1: Syntax & Base Verification (syntax-and-setup) compileall

Objective: Fast-fails the pipeline immediately if syntax errors, unclosed strings, or invalid indentations are committed.

python -m compileall app/ tests/ scripts/
Stage 2: Code Quality & Type Checking (code-quality) Ruff & MyPy

Objective: Enforces PEP 8 standards, organizes imports, removes dead code, and validates static types across FastAPI Pydantic models.

ruff check app/ tests/ scripts/
mypy --explicit-package-bases --ignore-missing-imports app/
Stage 3: Multi-Vector Security Scans (security-scans) Bandit, pip-audit, Safety, Gitleaks

Objective: Eliminates OWASP Top 10 vulnerabilities (SQL/NoSQL injection, insecure crypto), audits dependency CVEs, and prevents secret leaks.

bandit -r app/ -ll -s B104
pip-audit -r requirements.txt
safety check -r requirements.txt
Stage 4: Automated Testing & Coverage Suite (test-suite) Pytest & MongoDB 7.0

Objective: Spins up a healthy MongoDB 7.0 container, runs 39 Unit and API tests, and exports coverage.xml and test XML artifacts.

pytest tests/unit -v --cov=app --cov-report=xml:coverage.xml
pytest tests/api -v
Stage 5: SonarQube Clean Code Gate (sonarqube) SonarScanner / SonarCloud

Objective: Ingests coverage.xml to inspect code duplication, complexity, and security hot-spots. Cleanly skips if credentials are not yet configured.

sonar-scanner (driven by sonar-project.properties)
Stage 6: Docker Container Build & Scan (docker-build-and-scan) Buildx & Aqua Trivy

Objective: Assembles the deployable container image and scans Linux base layers and Python dependencies for CRITICAL/HIGH vulnerabilities.

docker build -t central-attendance-system:$SHA .
trivy image --severity CRITICAL,HIGH central-attendance-system:$SHA

5. Local Developer Pre-Push Verification Cheatsheet

QUICK VERIFICATION
Run this 4-step PowerShell sequence locally before pushing code to Git: 
# 1. Check Syntax
python -m compileall app/ tests/ scripts/

# 2. Check Style & Linter
ruff check app/ tests/ scripts/

# 3. Run SAST Security Scan
bandit -r app/ -ll -s B104

# 4. Run Test Suites
pytest tests/unit tests/api -v
